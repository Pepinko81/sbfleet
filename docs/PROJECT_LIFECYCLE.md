# Lifecycle and process semantics

Persist operation intent (`create`, `start`, `stop`, `restart`, `backup`, `restore`, `update`, `remove`), operation UUID, phase, started_at, old/target ref, backup id and a redacted error. Persist creation completion and last verified version. Never persist HEALTHY as truth.

Derived states: CREATING for incomplete create; STARTING/STOPPING/REMOVING while a live locked operation runs; STOPPED when valid project has no running containers; HEALTHY only when the entire service/probe contract passes; DEGRADED when some containers/probes fail; FAILED for interrupted/failed mutation needing recovery or invalid project configuration. NEW is conceptual absence, not a registry row. An interrupted journal plus released lock is FAILED until reconciled; do not guess that the last subprocess completed.

Create: validate inputs/tools → reserve identity/ports → private materialization → upstream secret generators → overlay → config/ownership checks → atomic valid-config checkpoint → optional start and probes → creation_complete=true only after all requested stages pass. `--resume` never regenerates existing secrets or wipes PGDATA. A stopped valid create is CREATED but not HEALTHY.

Start: authorize under continuous project lock (identity/paths/Compose/live ownership + no unresolved journal) → force Compose selectors from recomputed identity → `sh run.sh start --wait-timeout 180` → verify all services and probes → success. Already healthy is a validated no-op. Timeout is configurable with bounds (10–1800 seconds), never `--ignore-health-check`. Ordinary start refuses unresolved maintenance/destructive journals (FAILED, not STOPPED).

Stop: authorize → verify owned resources → `sh run.sh stop` → inspect no project containers running. Retain binds and named volumes. Already stopped succeeds. Ordinary stop **must not** overwrite unresolved RESTORING/UPDATING/REMOVING/BACKUP journals; it may halt containers and record subordinate stop evidence under the parent operation. Nested remove/backup/restore/update lifecycle calls use `manage_journal=False`. Restart uses upstream restart then complete probes; config changes require update/recreate instead. Do not automatically turn a stopped project on through restart; report STOPPED and suggest start.

Health: every expected container must run; every upstream healthcheck must be healthy, not starting. Malformed Docker enumeration fails closed (UNKNOWN/FAILED), never STOPPED. Failed/interrupted RESTORING/UPDATING/REMOVING/BACKUP journals dominate ordinary HEALTHY/STOPPED at all container occupancies; mere in-progress maintenance keeps runtime probes so nested start verify can succeed. Services without healthchecks require explicit probes: meta `/health` on internal port via a pinned helper if needed; functions via upstream health plus gateway smoke. DB SQL `SELECT 1` through in-container psql, Auth `/auth/v1/health`, REST service-key OpenAPI or known fixture endpoint, Storage health in container, Realtime tenant health, and Studio authenticated `/project/default` (follow bounded same-origin redirects to successful HTML). An unauthenticated Studio 401 is a security check, not sufficient health. Bound HTTP requests, don't print headers/tokens. No external DNS needed for local health.

Journal transitions: new backup/restore/update/remove refuse over unresolved maintenance (no silent overwrite, no generic `--force`). Update apply rebuilds the plan under lock; if it differs from the reviewed plan, refuse and return the authoritative plan. Create completion with requested start keeps final metadata writes under registry-before-project lock.

Removal: confirmation, successful backup by default, continuous lock via mutation authority, prove resource ownership from UUID + Compose labels + expected mounts + concrete resource IDs, delete only inventoried owned containers/networks/volumes by ID (never `--remove-orphans` or global prune), wipe only proven contained volumes trees, delete project metadata only after owned resources/data are handled. Unknown/renamed/foreign resources remain untouched and produce refusal or residual report. Partial deletion is REMOVING/FAILED and resumable; never rename a different project into its place.

All subprocess calls use argv arrays, no shell interpolation of user input. Shell is used only for fixed audited upstream script invocations and fixed helper commands with values passed as separate arguments. Set cwd, environment, timeouts; forward SIGINT/SIGTERM to process group; retain journals on interruption. Errors are not swallowed, pipeline success requires every stage's exit code. Logs/env children have special exit behavior in COMMAND_SPEC.
