# Secret and safety model

## Generation and storage

umask 077 before any filesystem/subprocess work. Project root/staging 0700; .env, metadata, captures and generated Compose 0600. Container-owned data directories retain the upstream UID/GID; do not chmod everything recursively. No secrets in Git, metadata, command suggestions or normal JSON. Refuse symlinks/hardlink tricks on managed secret files and atomically replace only owned regular files. Supported host model: Linux local filesystem with flock and readable `/proc/self/mountinfo` for destructive subtree proof — do not claim NFS/network-filesystem safety. Before recursive wipe of managed trees, refuse any unexpected mountpoint at or beneath the destructive root (ancestor checks alone are insufficient). Lock files validate the opened descriptor (regular file, owner, nlink==1) before truncate. Secret/file authority (type/owner/link/private mode) applies narrowly to project `.env`, metadata, locks, managed secret/config, and explicitly supplied recovery identity files — refuse unsafe files with actionable errors; never recursively chmod container-owned PGDATA.

Copy .env.example and vendor Compose into an operation-private scratch directory. Run exact pinned `sh utils/generate-keys.sh --update-env`, then `sh utils/add-new-auth-keys.sh --update-env` there. Require local Node>=16, OpenSSL; never accept Docker fallback. Capture both streams without echoing, discard on success/failure after emitting only a safe error code. Validate required values, absence of known defaults, lengths, unique values against sibling projects, JSON/JWK structure and that ANON/service roles differ. Copy only .env into deployment; keep original upstream Compose unmodified, render the four asymmetric environment mappings in the overlay. Delete scratch .old copies with the operation directory. No homemade crypto implementation.

Set DASHBOARD_USERNAME to `sb_<project12>` (unique, safe ASCII), random upstream DASHBOARD_PASSWORD, POOLER_TENANT_ID to project UUID's compact form. Storage tenant/bucket identifiers can remain internal defaults because all data/network resources are independent. Set public URL and Auth URL with `/auth/v1`. Blank OPENAI_API_KEY. Disable phone signup and phone auto-confirm until an operator configures real delivery; disable email signup until real SMTP is configured, while retaining the Auth service and admin operations. Never enable email auto-confirm merely to make production tests pass. User SMTP/provider secrets belong in .env. Doctor reports unavailable signup delivery separately from infrastructure health.

The dotenv reader is a strict data parser, never `source`, eval or a shell. Reject duplicate keys, malformed quotes, newlines, DEL/controls, and Compose-expandable interpolation (`$NAME`, `${…}`) in unquoted and double-quoted values — V1 refuses unsupported forms rather than reimplementing Compose expansion. Also refuse unquoted `$$` and unquoted leading whitespace after `=` (Compose would reinterpret those forms). Support generated JSON/base64 value forms, single-quoted literals, and Compose `$$` escaping via `dump_dotenv` (double-quoted). Accepted values must mean the same thing to sbfleet parse/write/validation/redaction/health and Docker Compose runtime. Do not silently rewrite existing operator files. Compose config/inspect are secret-bearing; parse in memory and redact known values plus credential-bearing URL fields recursively before any diagnostic output. Don't persist fully interpolated config.

## Output and privilege

`secrets P` lists names with `[REDACTED]`; `--reveal` explicitly warns on stderr before printing 0600-file values to stdout. No reveal through --json or debug. `connection P` provides nonsecret URLs/ports and admin-vs-runtime explanation, not passwords. `env P --admin -- COMMAND` grants selected long-lived DB admin authority deliberately; no default implicit admin. Runtime access requires the app's own role/credential file. Arbitrary child output cannot be reliably scrubbed: never capture it into fleet logs, warn that the explicitly launched process receives credentials. Environment variables are visible to same-user/root processes; this is not a secret vault.

Logs can contain application secrets. Ordinary diagnostics use **one configured boundary**: gather credential values from the same supported dotenv sources as authority (fleet `deployment/.env`; sandbox `.env` / `.env.local` / `supabase/.env(.local)` / one-level ancestor `.env(.local)`), then redact exact known credentials (passwords, JWT/admin/service secrets, SMTP credentials, OAuth/provider secrets/tokens, dashboard password, and other supported secret/token keys) plus credential-bearing URL userinfo **before** truncation/rendering/journal persistence. If a supported source exists but cannot be safely read/parsed, suppress raw detail and emit a bounded generic credential-safe-rendering failure — never fall back to an empty redactor and print subprocess text. Short/trivial values (ports, booleans, common usernames/database words) are not blindly globally replaced. Streaming logs use a stateful rolling redactor so secrets split across chunks cannot leak. Never claim arbitrary application log sanitization, and don't retain logs. Terminate child on interruption. Never print raw upstream generator output, Docker inspect, command environment or traceback with secret locals. Shell history must not store reveals or environment values. Explicit exceptions remain: `secrets --reveal` and authorized project/sandbox `env` child stdout.

Dashboard Basic authentication is upstream Envoy's job. HTTPS via operator-managed nginx is required before Internet access. API routes must preserve their own API-key/Auth semantics, not receive a new whole-site Basic auth layer. Local host users can reach loopback services; no hostile-user isolation claim.

## Backup and update security

All portable backups are age-encrypted, including project .env, pgdata, pgsodium key and function code, because complete recovery needs them and DB contents themselves contain secrets. Recipient public keys live in fleet.json; private identities live outside fleet/source trees. Encryption-key loss means backup loss. No plaintext backup export. Backup staging is 0700 with cleanup journals; never promise secure erasure on SSDs. Upstream update's plaintext config tgz lives only in restricted staging, never exposed as a fleet backup. Encrypt diagnostic config retention or delete it after verified promotion.

## Destructive boundary

Type slug interactively for restore/remove; explicit --yes in automation. --yes does not bypass ownership, corruption, pin or compatibility checks. Removal skips backup only with separate `--no-backup`. Never prune globally or delete by name resemblance. prior hardening work. prior release strengthens that boundary: Docker ABSENT vs UNKNOWN/FAILED are distinct (only exact missing-resource contracts authorize absence); invent reconciles containers, networks, and named volumes independently via Compose/project labels; expected service images come from the approved pinned vendor Compose snapshot (runtime `image_digests` are drift evidence only); foreign default-network names and unsupported `network_mode` refuse. Backup check failures prevent update/restore/remove by default. A Docker socket gives host-level power; base stacks do not mount it. sbfleet uses the operator's already-authorized local Docker access and does not create a privileged daemon.

Sandbox details in DEV_SANDBOX / implementation note are mandatory: no login/link, no remote flags, no Cloud token, isolated CLI config/keyring disabled, crash-consistent adoption bound to canonical root + unique CLI project ID + verified resource inventory. Sandbox authority dotenv uses a strict supported grammar (malformed lines refuse) and denies libpq/Docker/Compose targeting variables; endpoint locality uses endpoint-specific schemes and an empty PostgreSQL URI query-parameter allowlist matching pinned CLI 2.118.0 local DB_URL (any query target override refuses). An unrestricted same-user agent can bypass wrappers (edit adoption records, run Docker/CLI directly); actual enforcement requires separate account/daemon/VM without long-lived project or Cloud credentials. Do not claim sbfleet provides that boundary.
